# 라이선스, 어디까지 써도 될까요?

> 무료로 받을 수 있다는 것과 내 서비스에 사용할 수 있다는 것은 다릅니다.

라이선스는 코드·이미지·폰트 등을 **어떤 조건으로 사용해도 되는지 정한 허락**입니다. 이 가이드는 종류별 핵심 조건을 읽는 입문 안내입니다. 실제 사용 여부는 해당 파일에 적용되는 라이선스 버전과 이용약관이 기준이며, 계약이나 공개 범위가 불명확한 경우에는 권리자 또는 법률 전문가에게 확인하세요.

## 먼저, 내가 하려는 일을 구분하세요

- **상업적 사용:** 유료 앱, 고객에게 납품하는 웹사이트, 광고·판매를 위한 콘텐츠 등에 사용하기.
- **수정:** 코드를 바꾸거나 이미지·폰트를 가공하기.
- **재배포:** 파일을 다른 사람에게 전달하거나 앱·템플릿·다운로드 패키지에 포함하기.

웹사이트에서 사용만 한다고 생각해도 브라우저로 보내는 JavaScript나 폰트 파일은 배포에 해당할 수 있습니다. 서버 안에서만 실행되는 코드와 사용자에게 전달되는 파일을 나눠 확인하세요. [Mozilla의 배포 설명](https://www.mozilla.org/en-US/MPL/2.0/FAQ/#what-does-distribute-mean)

## DRH의 판정 태그는 이렇게 읽으세요

| 판정 | 뜻 | 다음 행동 |
|---|---|---|
| 가져오기 가능 | 복사·적용 후보로 분류한 출처 | License evidence에서 대상 파일과 조건을 확인한 뒤 사용 |
| 참고 전용 | 화면이나 아이디어를 살펴보는 용도 | 코드·이미지 복사 허락이 있는지 별도로 확인 |
| 제한 | 사용 범위에 제한이 있는 출처 | 내 용도가 허용되는지 약관이나 별도 허락 확인 |

이 태그는 DRH의 분류이며 법적 허가증이 아닙니다. 저장소가 MIT여도 로고·사진·상용 폰트·외부 예제까지 같은 조건이라는 뜻은 아닙니다. [출처 탭](#/sources)에서 Original과 License evidence를 함께 열어 보세요.

## 코드 라이선스: 상업용으로 쓸 수 있나요?

아래의 **가능**은 각 조건을 지킬 때 가능하다는 뜻입니다. 특히 소스 제공 의무가 있는 라이선스는 앱에 결합하는 방식과 배포 형태까지 확인해야 합니다.

| 종류 | 상업적 사용 | 핵심 조건 |
|---|---|---|
| MIT | 가능 | 저작권 표시와 라이선스 전문을 복사본 또는 상당한 부분에 유지 |
| BSD 2-Clause / 3-Clause | 가능 | 저작권·조건·면책 문구 유지. 3-Clause는 허락 없이 저자 이름을 홍보·보증에 사용하지 않기 |
| Apache 2.0 | 가능 | 라이선스·관련 고지 보존, 변경 파일에 수정 표시, 해당 NOTICE 내용 전달 |
| MPL 2.0 | 가능 | 외부 배포 시 MPL 적용 파일과 수정본의 소스를 MPL로 제공하고 얻는 방법 안내 |
| GPL v3 | 가능 | 적용 대상 저작물 배포 시 GPL 조건과 그에 대응하는 소스 제공 의무 준수 |
| AGPL v3 | 가능 | GPL 계열 의무에 더해 수정된 프로그램의 네트워크 사용자에게 대응 소스를 받을 기회 제공 |

### MIT / BSD: 고지문을 지키며 가져오기

유료 서비스에도 사용할 수 있고 수정도 가능합니다. MIT 코드 일부를 가져왔다면 원저작자 표시와 라이선스 전문을 함께 보관하고 배포물에서도 유지하세요. 원본 LICENSE를 내 이름으로 덮어쓰지 마세요. BSD는 배포 형태에 따른 고지 조건과 정확한 버전을 확인합니다. [MIT 전문](https://choosealicense.com/licenses/mit/), [BSD 3-Clause 전문](https://opensource.org/license/bsd-3-clause)

### Apache 2.0: 수정 표시와 NOTICE도 확인

상업적 사용과 수정·배포가 가능합니다. 배포할 때 라이선스 사본을 전달하고, 수정한 파일에는 변경 사실을 표시합니다. 원본에 NOTICE가 있으면 관련 고지 내용을 함께 전달해야 합니다. 기여자가 제공하는 일정 범위의 특허 허락이 포함되지만, 브랜드·상표 사용 허락까지 주는 것은 아닙니다. [Apache 2.0 전문 §3–6](https://www.apache.org/licenses/LICENSE-2.0)

### MPL / GPL / AGPL: 무료 여부보다 공개 범위

**Copyleft**는 배포 등의 조건이 충족되면 적용 대상 소스와 수정본에도 같은 라이선스의 자유를 이어 주도록 하는 방식입니다.

- **MPL 2.0:** 파일 단위가 기준입니다. MPL 코드를 포함하지 않는 별도 파일까지 무조건 MPL로 바꿔야 하는 것은 아닙니다. 축소된 JavaScript를 배포할 때도 원본 소스 제공 안내가 필요할 수 있습니다. [Mozilla FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)
- **GPL v3:** 상업적 판매를 금지하지 않습니다. 적용 대상 프로그램이나 이를 바탕으로 한 결합 저작물을 배포하면 수령인에게 GPL 권리와 대응 소스를 제공해야 합니다. 단순히 개발 도구로 실행했다는 이유만으로 내 결과물 전체가 GPL이 되지는 않습니다. [GPL v3 전문 §0, §2, §4–6](https://choosealicense.com/licenses/gpl-3.0/)
- **AGPL v3:** 수정한 프로그램을 네트워크로 서비스하는 경우에도 그 버전과 상호작용하는 사용자에게 대응 소스 접근을 제공해야 합니다. 서버 코드라서 배포 조건을 신경 쓰지 않아도 된다고 가정하면 안 됩니다. [AGPL v3 전문 §13](https://choosealicense.com/licenses/agpl-3.0/)

LGPL이나 별도 예외 조항을 만났다면 GPL과 동일하게 단정하지 마세요. 라이브러리 수정·링크·재결합 조건은 해당 버전의 전문을 확인해야 합니다.

## 이미지·문서: Creative Commons 읽기

Creative Commons(CC)는 사진·글·일러스트 등에서 자주 보입니다. 약어를 조합해서 조건을 표시합니다.

| 표시 | 의미 | 사용 판단 |
|---|---|---|
| CC0 | 가능한 범위에서 저작권 등을 포기하는 도구 | 상업적 이용·수정 가능. 초상권·상표권 등은 별도 확인 |
| BY | 저작자 표시 | 저작자·출처·라이선스 링크와 변경 여부 등 요구 고지 포함 |
| SA | 동일조건변경허락 | 수정물을 공유할 때 지정된 동일 또는 호환 라이선스 적용 |
| NC | 비영리 | 상업적 사용은 이 허락에 포함되지 않음. 필요하면 별도 허락 |
| ND | 변경금지 | 수정물 공유는 허용되지 않음. 원본 공유도 나머지 조건 준수 |

**CC BY**와 **CC BY-SA**는 조건을 지키면 상업적으로 사용할 수 있습니다. **CC BY-ND**도 수정하지 않은 자료의 상업적 공유는 가능하지만 수정물 공유는 안 됩니다. **NC가 붙은 조합**은 비영리 조건이 추가됩니다. 무료로 운영하는 사이트라는 이유만으로 NC에 해당한다고 단정하지 말고 실제 이용 목적을 확인하세요. [Creative Commons 공식 안내](https://creativecommons.org/cc-licenses/)

출처 표시 예시는 다음과 같습니다. 실제 자료에 제공된 고지를 보존하고, 아래 괄호를 실제 정보로 채우세요.

```text
이미지: [작품명] — [저작자]
원본: [원본 URL]
라이선스: CC BY 4.0 — https://creativecommons.org/licenses/by/4.0/
변경: 색상 보정 및 일부 자르기
```

## 폰트: OFL과 상용 폰트 구분하기

**SIL Open Font License 1.1(OFL)** 폰트는 상업용 웹사이트·앱·디자인에 사용할 수 있습니다. 폰트 파일을 포함해 배포할 때는 저작권·OFL 문구를 유지하고, 폰트 자체를 단독으로 판매하지 않아야 합니다. 수정 폰트를 배포한다면 Reserved Font Name(예약된 이름) 조건도 확인하세요. 해당 폰트로 만든 문서나 디자인까지 OFL로 공개해야 하는 것은 아닙니다. [OFL 공식 전문](https://openfontlicense.org/open-font-license-official-text/)

상용 폰트는 상품별 계약을 읽어야 합니다. 데스크톱 디자인 사용권이 웹폰트 호스팅·앱 내장·파일 재배포까지 포함하는지 따로 확인하세요. 폰트 파일을 다운로드했다는 사실만으로 모든 용도가 허용되지는 않습니다.

## 라이선스 없음·유료 에셋은 어떻게 하나요?

**라이선스가 없으면 자유롭게 복사해도 된다고 가정하지 않습니다.** 공개 GitHub 저장소를 볼 수 있는 것과 다른 제품에 코드를 재사용하는 허락은 별개입니다. 필요한 허락이 확인되지 않으면 권리자에게 문의하거나 조건이 명확한 대체재를 고르세요. [라이선스가 없는 경우](https://choosealicense.com/no-permission/)

유료 템플릿·사진·아이콘은 구매한 상품의 약관에서 다음을 찾습니다.

- 상업적 사용과 고객 납품이 포함되는가?
- 프로젝트·사용자·도메인 수 제한이 있는가?
- 원본 파일을 다른 사람에게 전달하거나 템플릿으로 재판매할 수 있는가?
- 출처 표시가 필요한가? 인물·브랜드가 포함된 자료의 별도 권리는 확인됐는가?

약관에 없거나 해석이 모호한 용도는 구매했다는 이유만으로 허용된 것으로 처리하지 마세요. 확인한 약관 버전과 별도 허락을 함께 보관하면 나중에 사용 근거를 찾기 쉽습니다.

## 내 프로젝트에 넣기 전, 5단계

1. **대상을 정합니다.** 코드·이미지·폰트 중 실제 가져올 파일을 적습니다.
2. **원본을 확인합니다.** 해당 버전의 LICENSE, NOTICE, 파일별 고지와 예외를 읽습니다.
3. **내 용도와 대조합니다.** 상업적 사용·수정·배포·서버 제공 여부를 표시합니다.
4. **조건을 이행합니다.** 고지문 유지, 변경 표시, 필요한 소스 제공 등을 배포물에 반영합니다.
5. **근거를 보관합니다.** 원본 URL·버전·라이선스 전문·수정 내역을 함께 기록합니다.

MIT 컴포넌트를 유료 앱에 넣는 경우라면 대상 코드가 실제 MIT인지 확인하고 원본 저작권·라이선스를 포함합니다. 같은 저장소의 데모 사진은 별도 라이선스일 수 있으므로 따로 확인합니다. NC 사진을 판매 페이지에 쓰려는 경우에는 상업적 사용 허락을 별도로 받거나 다른 사진을 고릅니다.

## Coding Agent에게 전달할 문장

```text
이 자료를 내 프로젝트에 적용하기 전에 실제 복사할 파일의 라이선스를 확인해 줘.
사용 목적: [상업용 웹사이트 / 고객 납품 / 개인 실습 등]
배포 방식: [웹 브라우저 / 앱 설치 파일 / 서버에서만 실행 등]
원본 URL과 버전: [링크와 버전]

코드·이미지·폰트를 따로 확인하고, 원본 LICENSE와 NOTICE를 보존해 줘.
필요한 고지·변경 표시·소스 제공 조건을 정리하고 배포물에 반영해 줘.
허락이 불명확한 파일은 임의로 사용 가능하다고 결론 내리지 말고 표시해 줘.
```

Agent의 요약만 믿고 끝내지 말고 원본 고지와 최종 배포물을 대조하세요. 실제 코드를 옮기는 과정은 [Demo와 Code를 내 프로젝트에 붙이는 법](#/guides/apply-demo-code)으로 이어집니다.
