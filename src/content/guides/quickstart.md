# DRH 5분 시작하기

> Reference 하나를 골라 Coding Agent에 실제 적용하는 가장 짧은 방법

DRH(Design Reference Hub)는 잘 만들어진 화면의 디자인 규칙과 코드를 모아 둔 곳입니다. 이 Guide를 따라 하면, 하나의 Reference를 골라서 Coding Agent(AI가 코드를 대신 써 주는 도구)에게 전달하고, 실제 화면 하나를 만들 수 있습니다.

이 Guide는 "일단 해 보기"에 집중합니다. DESIGN.md를 직접 만드는 방법은 [내 프로젝트 DESIGN.md 만들기](#/guides/create-design-md)를, Demo와 코드를 프로젝트에 옮기는 자세한 과정은 [Demo와 Code를 내 프로젝트에 붙이는 법](#/guides/apply-demo-code)을 읽어 주세요.

---

## 전체 흐름

| 단계 | 할 일 | 걸리는 시간 |
|---|---|---|
| 1–3 | 마음에 드는 Reference 찾기 | 2분 |
| 4–6 | 필요한 파일 복사 | 1분 |
| 7–8 | 프로젝트에 넣고 Agent에게 전달 | 1분 |
| 9–10 | 화면 만들고 확인 | 1분 |

---

## Step 1. 탐색에서 원하는 Reference 찾기

**지금 할 일:** [Explore](#/explore) 페이지를 엽니다. 카드를 스크롤하면서 "이 느낌이 좋다"는 Reference를 하나 고르세요.

**왜:** DRH의 Reference는 실제 서비스에서 검증된 디자인 규칙을 정리해 둔 것입니다. 처음부터 색상이나 간격을 직접 정할 필요 없이, 마음에 드는 것을 골라서 시작할 수 있습니다.

**완료 확인:** 카드 하나를 클릭할 수 있는 상태입니다.

---

## Step 2. Demo 직접 움직여 보기

**지금 할 일:** 고른 Reference 카드에 Demo가 보이면, 마우스로 직접 움직여 보세요. 버튼을 클릭하고, 스크롤하고, hover 해 보세요.

**왜:** 스크린샷만으로는 실제 동작(애니메이션, 전환 효과, 반응형 레이아웃)을 알 수 없습니다. 직접 만져 봐야 "이 효과를 쓸지 말지" 판단할 수 있습니다.

**완료 확인:** Demo 안에서 최소 하나의 상호작용(클릭, hover, 스크롤)을 해 봤습니다.

---

## Step 3. WORKING DEMO인지 확인

**지금 할 일:** Demo 영역에 표시된 상태를 확인하세요.

- **WORKING DEMO**: 실제 동작하는 코드입니다. 그대로 가져갈 수 있습니다.
- **PROTOTYPE**: 구도와 개념을 보여 주는 예시입니다. 일부 동작이 빠져 있을 수 있습니다.
- **OFFICIAL LIVE**: 원본 사이트로 연결됩니다.

**왜:** PROTOTYPE을 완성된 코드로 착각하면, Agent가 만든 결과물에서 빠진 동작을 찾느라 시간을 낭비합니다.

**완료 확인:** 지금 보고 있는 Demo의 상태(WORKING DEMO / PROTOTYPE / OFFICIAL LIVE)를 알고 있습니다.

---

## Step 4. 상세 화면 열기

**지금 할 일:** Reference 카드를 클릭해서 상세 페이지로 들어가세요. 오른쪽에 여러 탭(Agent, DESIGN.md, CSS, HTML 등)이 보입니다.

**왜:** 상세 페이지에는 Coding Agent에게 전달할 파일들이 준비되어 있습니다. 각 탭이 다른 역할을 합니다. 지금은 Agent와 DESIGN.md 두 가지만 쓸 겁니다.

**완료 확인:** 상세 페이지가 열렸고, 오른쪽에 탭이 보입니다.

---

## Step 5. Agent → Extended 복사

**지금 할 일:** **Agent** 탭을 클릭하세요. Compact와 Extended 두 버전이 있습니다. **Extended**를 선택하고 전체 내용을 복사하세요. 파일로 저장한다면 `docs/reference-agent.md`라는 이름을 추천합니다.

Agent Package(에이전트 패키지)란 "AI에게 일을 시키는 설명서"입니다. 목표, 동작 규칙, 코드 예시, 검수 조건이 모두 들어 있습니다.

- **Compact**: 핵심만 담은 짧은 버전. 이미 규칙을 읽힌 뒤 추가 작업할 때 유용합니다.
- **Extended**: 목표부터 검수까지 전부 담은 버전. 처음 적용할 때는 이쪽을 쓰세요.

**왜:** Agent에게 "예쁘게 만들어 줘"라고 하면 매번 다른 결과가 나옵니다. Extended는 "본문 16px, 카드 패딩 24px, 이 색상만 사용" 같은 구체적인 숫자를 포함하고 있어서 결과가 일정합니다.

**완료 확인:** Extended 내용을 클립보드에 복사했거나, `docs/reference-agent.md` 파일로 저장했습니다.

---

## Step 6. DESIGN.md가 있으면 함께 저장

**지금 할 일:** **DESIGN.md** 탭이 있는지 확인하세요. 있으면 내용을 복사해서 프로젝트 루트에 `DESIGN.md`라는 이름으로 저장하세요.

DESIGN.md는 "계속 지킬 디자인 규칙"입니다. 색상, 간격, 모서리 값 등이 정리되어 있어서 한 번 저장해 두면 여러 화면을 만들 때 일관성을 유지할 수 있습니다.

모든 Reference에 DESIGN.md 탭이 있는 것은 아닙니다. 없으면 Step 5에서 복사한 Agent Package만으로 진행하세요.

나중에 직접 DESIGN.md를 만들고 싶다면 [내 프로젝트 DESIGN.md 만들기](#/guides/create-design-md)를 참고하세요.

**왜:** Agent Package는 "이번 작업"을 위한 설명서이고, DESIGN.md는 "앞으로 계속" 지킬 규칙입니다. 둘 다 있으면 Agent가 더 일관된 결과를 만듭니다.

**완료 확인:** DESIGN.md 파일을 프로젝트 루트에 저장했거나, 탭이 없어서 건너뛰었습니다.

---

## Step 7. 프로젝트에 파일 넣기

**지금 할 일:** 저장한 파일을 프로젝트 폴더에 넣으세요. 아래는 추천 구조입니다. 이미 팀의 폴더 규칙이 있다면 그 규칙을 따르세요.

```text
my-project/
  DESIGN.md                  ← 디자인 규칙 (있을 때)
  docs/reference-agent.md    ← Agent Package
  docs/reference-source.md   ← 출처 기록 (있을 때)
  src/                       ← 기존 코드
```

**왜:** 파일이 프로젝트 안에 있어야 Agent에게 "이 경로의 파일을 읽어"라고 정확히 지시할 수 있습니다. 파일을 두는 것만으로 Agent가 자동으로 읽지는 않습니다. 다음 단계에서 직접 알려 줄 겁니다.

**완료 확인:** 프로젝트 폴더 안에 파일이 저장되었습니다.

---

## Step 8. Coding Agent에게 읽으라고 말하기

**지금 할 일:** 사용 중인 Coding Agent(Cursor, Claude Code, Codex, Windsurf 등 어떤 것이든)에게 아래 prompt를 복사해서 보내세요.

```text
먼저 ./DESIGN.md와 ./docs/reference-agent.md를 읽어줘.
핵심 디자인 토큰(색상, 글자 크기, 간격, 모서리)과 제약 사항을 요약해 줘.
현재 프로젝트의 프레임워크와 기존 컴포넌트도 확인해 줘.
기존 규칙과 충돌하는 부분이 있으면 구현 전에 알려 줘.
```

DESIGN.md 없이 Agent Package만 있다면, 첫 줄을 `먼저 ./docs/reference-agent.md를 읽어줘.`로 바꾸세요.

**왜:** 어떤 Coding Agent를 쓰든, 파일 경로를 직접 넣어 주는 방법이 가장 확실합니다. 도구마다 설정 메뉴가 다르고 바뀔 수 있지만, "이 파일을 읽어"라는 지시는 어디서든 동작합니다.

**완료 확인:** Agent가 파일을 읽고 디자인 토큰을 요약해 줬습니다. 만약 "파일을 찾을 수 없다"고 나오면, 경로가 맞는지 확인하세요.

---

## Step 9. 화면 하나만 구현시키기

**지금 할 일:** Agent에게 아래 prompt를 보내세요. 대괄호 안의 내용은 본인 프로젝트에 맞게 바꾸세요.

예제 — 팀 프로젝트 목록 페이지:

```text
방금 읽은 디자인 규칙을 적용해서 팀 프로젝트 목록 페이지를 만들어 줘.
포함할 요소: 페이지 제목, 검색 입력, 상태 필터, 프로젝트 카드 6개.
CSS의 canvas/surface/text/primary 토큰을 그대로 사용해.
기존 라우터와 컴포넌트를 재사용하고 새 패키지는 추가하지 마.
390px에서는 1열, 1440px에서는 3열로 카드를 배치해.
검색과 필터는 실제로 동작하게 해 줘. 빈 결과 상태도 만들어.
끝나면 변경한 파일 목록과 실행 방법을 알려 줘.
```

**왜:** 한 번에 사이트 전체를 만들게 하면 문제가 생겼을 때 원인을 찾기 어렵습니다. 화면 하나만 먼저 만들어서 디자인 규칙이 잘 적용되는지 확인하세요.

**완료 확인:** Agent가 코드를 생성했고, 실행 방법을 알려 줬습니다.

---

## Step 10. 실제 화면 비교

**지금 할 일:** 만들어진 화면을 브라우저에서 열고, DRH의 Demo와 나란히 비교하세요.

확인할 것:

| 항목 | 확인 방법 |
|---|---|
| 색상 | Demo의 배경/글자/강조색과 같은지 |
| 간격 | 카드 사이, 패딩이 Demo와 비슷한지 |
| 글자 크기 | 제목/본문이 너무 크거나 작지 않은지 |
| 반응형 | 브라우저 폭을 줄여서(390px) 1열이 되는지 |
| 클릭 | 버튼, 검색, 필터가 실제로 동작하는지 |

색상이 다르게 보인다면:
- CSS 파일이 실제로 로드됐는지 확인하세요.
- 기존 전역 스타일이 덮어쓰고 있는지 브라우저 개발자 도구(F12)에서 확인하세요.

간격이 매번 달라진다면:
- "카드 패딩은 space-4"처럼 토큰 이름과 사용 위치를 한 쌍으로 지정하세요.

Agent가 잘린 코드를 만들면:
- Extended를 파일로 저장하고 경로를 명시했는지 확인하세요.
- 한 컴포넌트씩 나눠서 요청하세요.

**완료 확인:** 실제 화면이 Demo와 비슷한 느낌으로 동작합니다.

---

## ✅ 여기까지 됐으면 성공

- [ ] Explore에서 Reference를 골랐다
- [ ] Demo를 직접 움직여 봤다
- [ ] WORKING DEMO / PROTOTYPE / OFFICIAL LIVE 상태를 확인했다
- [ ] Agent Package(Extended)를 저장했다
- [ ] DESIGN.md를 저장했다 (있을 때)
- [ ] Agent가 파일을 먼저 읽었다
- [ ] 화면 하나를 구현했다
- [ ] 실제 화면과 Demo를 비교했다
